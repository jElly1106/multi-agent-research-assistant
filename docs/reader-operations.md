# Reader 部署、配置与运行风险

更新：2026-10-18。适用于当前任务分支的独立 Reader；当前验证范围见
[当前状态](reader-status.md)，本文不代表跨成员联调已通过。

## 换机必须重新准备什么

Git 只迁移受版本控制的代码和文档，不迁移系统/进程环境变量、本地 `.env`、
`.venv`、已下载论文、临时结果或内存缓存。容器、CI、远程服务器和 IDE 的运行
进程也需要各自获得配置；仅在另一个终端设置变量不会更新已启动的进程。

1. 拉取所需分支/提交，在目标机器创建 Python 虚拟环境，安装 `requirements.txt`。
   需要 PDF 时另装 `requirements-reader-pdf.txt`。依赖采用版本范围，未提供锁文件，
   新机器解析出的版本可能不同；应记录实际版本并重跑离线测试。不要复制 Windows 虚拟环境到其他系统。
2. 在实际启动 Reader 的进程中注入下表配置，或自行创建被 Git 忽略的本地 `.env`。
   Reader 导入时调用 `load_dotenv()`，默认不覆盖已存在的环境变量；切换模型时应
   检查旧进程值是否仍生效。仓库目前没有 `.env.example`。
3. 重新准备 PDF 和输入 JSON，更新本地路径/权限。相对 PDF 路径以当前工作目录
   为基准。输出父目录必须存在，`--output` 指定的文件必须尚不存在。
4. 临时目录必须可写，运行环境必须允许启动子进程。Python API 脚本使用
   `if __name__ == "__main__":` 保护入口；交互式 Notebook/受限容器中的 spawn
   行为需另行验证。当前实测环境为 Windows，未声称跨平台部署验收完成。

| 配置项 | 必要性与实际行为 |
| --- | --- |
| `OPENAI_API_KEY` | 默认模型适配器必需；由环境/部署密钥管理注入，不写入代码或 Git |
| `LLM_MODEL` | 必需，必须是目标账号/业务空间已获权限的模型 ID；代码不自动选择 |
| `OPENAI_BASE_URL` | 第三方网关需显式配置正确的 HTTP(S) API 根地址，不能填写 `/chat/completions` 或 `/responses` 端点；省略时走客户端默认服务配置，不会自动选百炼 |
| `LLM_API` | 默认 `chat_completions`，可选 `responses`；服务须支持相应接口及严格 JSON Schema 结构化输出 |
| `READER_USE_LLM` | 去除首尾空白后等于 `0` 时禁用默认模型；默认启用，`false` 不等于禁用 |
| `READER_ENABLE_THINKING` | 可选，只有 `0`/`1` 且仅支持 `chat_completions`；只在提供者支持 `enable_thinking` 时设置，否则不设置 |

已有 `DASHSCOPE_API_KEY` / `DASHSCOPE_BASE_URL` 不会自动映射。可在确认这两个变量
在目标进程有效后，按 [当前状态页](reader-status.md) 的 PowerShell 示例映射；
示例模型只是本次测试使用值，不保证目标账号可用。服务区域、业务空间、余额、
模型权限、接口和思考参数都须匹配。不要打印密钥验证，也不要将真实密钥粘贴到文档。
Reader 与 Coordinator 共享部分环境变量；Reader 的接口/思考开关不代表其他 Agent 已支持。

## 启动检查与成功判据

先在项目根目录运行不联网检查（以下不会替你安装依赖或配置模型）：

```powershell
& .\.venv\Scripts\python.exe -B -m research_assistant.reader_cli --help
& .\.venv\Scripts\python.exe -B -m research_assistant.reader_cli --input input.json --output preparation.json --offline
```

`input.json` 由调用者提供，格式见 [独立运行](reader-standalone.md)。离线模式仍可
解析本地 PDF，但不能证明模型可用。`--download-arxiv --no-llm` 可单独检查网络准备；
确认预算后才进行一次小样本模型检查，逐字段对照来源。

CLI 正常退出、JSON 合法、`paper_analysis` 存在，都不等于模型调用成功。缺密钥/
模型、服务失败、过滤或截断、预算不足可能返回摘要回退或空字段。检查日志以及
`acquisition`（仅下载入口）、`preparation`、`details.issues`、`field_sources` 和
`budget.events`；`details.status=ok` 也不是全文完整覆盖或语义正确的证明。
仅返回 `paper_analysis` 的节点会丢掉这些内部诊断，联调验收应另用独立入口保留诊断。
无 PDF 时 `local_pdf_missing` 可以是预期的摘要模式，不一定是部署故障。

## 已知风险与处理

| 情况 | 影响与处理 |
| --- | --- |
| 欠费、403/401、429、网络/TLS/代理问题 | 可能保守降级；确认账号权限/余额和目标进程网络，不能把空字段当正常提取。配置参数错误和编程错误仍可能直接抛出异常 |
| 模型切换或依赖升级 | 网关的接口、严格 Schema、输出上限和思考扩展可能不兼容；重跑离线回归后做授权的小样本真实测试 |
| 默认预算不适合所选模型 | 默认上下文16384、输出2048、最多50次、预留总额200000；UTF-8 字节估算不是精确 token 或账单，思考输出可能截断。按模型调整，不承诺实际费用上限 |
| 直接调用底层 P0/P2 | 没有统一批次预算，默认客户端最多2次重试；有费用约束时使用 `run_reader`/CLI，统一入口默认不自动重试 |
| 长时间执行与高内存 | 模型请求超时120秒不是整批截止时间；下载超时不是硬墙钟上限。PDF 隔离逐篇默认60秒、可选1–4 worker；大小/页数和缓存编码容量都不是 OS 内存上限 |
| 扫描件、复杂表格/多栏、损坏/加密 PDF | 无 OCR 或版式重建，可能缺页、错序、解析失败或无文本；人工核对准备层，不将缺失内容补造 |
| 论文映射错误或模型误解 | 标题/URL 合法、引句能匹配不证明论文身份或语义支持；人工核对论文和字段来源。默认字符串候选可并列，`reconcile=True` 也不保证解决数值矛盾 |
| arXiv 限流/重定向/版本变化 | 自动获取仅限官方支持 URL，拒绝重定向且不重试；无版本 URL 的内容可能变化。保存收据版本/哈希；其他来源显式提供本地 PDF |
| 隐私与结果文件 | 开启模型会将摘要、全文块或协调证据发往配置的服务，HTTP 根地址不提供传输加密；使用可信 HTTPS 服务。日志、诊断、JSON 和临时快照可能包含论文正文，不应当作无敏感信息文件公开 |
| 临时文件和缓存 | 正常结束/可处理异常会清理临时 PDF；强制终止或断电不保证清理。内存缓存随进程消失，不缓存模型响应；重复运行可能再次下载/付费调用 |

不要将密钥、`.env`、真实论文、原始结果和缓存纳入版本控制；`.gitignore` 不是对
任意自定义路径的保护，提交前仍需检查暂存内容。CLI 的禁用开关会临时修改进程环境，
不要在同一进程里并发调用不同模型开关的 CLI；多进程/多机器下载也不共享限流锁。

`main.py` 仍运行 demo 编排，配置成功不会自动接入正式 Reader。正式接入需要显式
选择摘要节点或全文节点，并确认 Search 完整论文列表、Reader 完整替换及下游字段
语义；这仍是后续联调工作，不属于本文验证结论。
